接入前准备

  • 宿主网页完成用户登录并获得 liveUserId、imUserId、liveToken。
  • 宿主动态传入 sceneType（1 直播间，2 IM 群）与 sceneId，SDK 不内置固定场景。
  • 登记宿主域名：游戏只接受白名单域名的父页面。请提供宿主页面的完整源（协议 + 域名 + 端口），例如 https://test2.kzb001.net（已登记）。
  • 正式环境宿主页面必须为 HTTPS。

本地联调白名单

  • 本地开发页面直接使用已登记的端口启动即可联调测试环境，例如 http://localhost:9560。
  • 白名单按「协议 + 域名 + 端口」完全匹配：http://127.0.0.1:9560、局域网 IP（如 http://192.168.1.10:9560）、其他端口都视为不同来源，需要单独登记。
  • 直接双击打开 HTML（file://）无法登记，必须通过本地 HTTP 服务访问。
  • 需要新增本地端口或测试域名时，把完整源发给游戏方登记，登记生效后刷新页面即可，无需更新 SDK。

5 分钟快速接入

  1. 页面引入 cocos_game_web.js。
  2. 准备一个已布局的容器元素（建议宽高比 375:211）。
  3. 用户登录后调用 CocosGameWeb.open，传入容器、游戏地址和会话。
  4. 离开页面或组件卸载时调用 close()。

import { useEffect, useRef } from 'react';

export function NiuniuGame({ user, sceneId }) {
  const containerRef = useRef(null);

  useEffect(() => {
    const game = window.CocosGameWeb.open({
      container: containerRef.current,
      gameUrl: 'https://niuniu-web-test.pages.dev/',
      session: {
        liveUserId: user.uid,
        imUserId: user.imUserId,
        liveToken: user.token,
        sceneType: 2,
        sceneId,
      },
      onError: (error) => console.error('游戏启动失败', error),
    });
    return () => game.close();
  }, [user.uid, user.token, sceneId]);

  return <div ref={containerRef} style={{ width: '100%', aspectRatio: '375 / 211' }} />;
}

SDK 不提供生产登录。UID、Token、Scene Type、Scene ID 必须由宿主页面传入；Token 只通过 postMessage 发给游戏域名，不会出现在 iframe 地址里。

打开与关闭游戏

CocosGameWeb.open(options) 在容器内创建 iframe 并返回控制句柄。同一容器重复打开前请先 close() 旧句柄。

session 参数

字段必填规则
liveUserId是宿主登录后的直播 UID（登录响应 uid），用于大厅鉴权，正整数
imUserId是宿主登录后的 IM UID（登录响应 userinfo.imUserId），用于识别本人座位，正整数
liveToken是宿主登录后的有效 Token
sceneType是1 直播间，2 IM 群
sceneId是当前场景 ID，按字符串原样传入
tableId否不传或 0 自动选择，正整数指定桌台
clientVersion否宿主版本号
deviceType否默认 H5

容器要求

  • 容器在 open 前已插入页面并有非 0 尺寸，iframe 会撑满容器。
  • 建议宽高比 375:211；其他比例游戏会等比适配，多余区域以背景补齐。
  • 牌桌元素随容器大小等比缩放，电脑浏览器上容器越大显示越大，无需单独适配。
  • 宿主改变容器尺寸（横竖屏切换、展开收起）时游戏自动重新布局，无需通知。

按钮配置

牌桌左上角返回按钮与右下角大屏按钮，宿主可以隐藏，或改写点击行为。

CocosGameWeb.open({
  // ...容器、地址、会话
  showBackButton: false,        // 隐藏返回按钮，默认 true
  showFullscreenButton: false,  // 隐藏大屏按钮，默认 true

  onBack() {                    // 改写返回按钮：例如回到直播间
    game.close();
    router.back();
  },
});
  • 不传 onBack 时，点击返回默认关闭游戏。
  • 玩家在座时点击返回，游戏会先弹出离座确认，确认后才通知宿主。
  • 改写大屏按钮见下方「全屏」。

全屏

默认全屏

点击大屏按钮时，SDK 将 iframe 撑满整个视口（position: fixed），并锁定页面滚动；再次点击还原。宿主也可以主动调用：

game.setFullscreen(true);   // 进入全屏
game.setFullscreen(false);  // 退出全屏

自定义全屏

传入 onFullscreenRequest 后，SDK 不再改动 iframe 样式，由宿主自行调整布局，再调用 updateFullscreenState 同步游戏内的全屏图标：

const game = CocosGameWeb.open({
  // ...
  onFullscreenRequest(isFullscreen) {
    gameContainer.classList.toggle('expanded', isFullscreen);
    game.updateFullscreenState(isFullscreen);
  },
  onFullscreenChange(isFullscreen) {
    console.log(isFullscreen ? '进入全屏' : '退出全屏');
  },
});

手机网页全屏后游戏固定横屏显示；用户竖着拿手机时游戏画面自动旋转铺满。

弹窗

下注、规则与记录、离座确认等游戏弹窗，遮罩始终铺满游戏当前区域：内嵌时只盖住宿主给的游戏区域，全屏时盖满整屏；旋转、全屏切换或宿主改变容器尺寸时遮罩自动调整。

弹窗范围

dialogScope效果
'game'（默认）弹窗只在游戏区域内显示，宿主页面其他内容可正常操作
'fullscreen'弹窗出现时游戏临时全屏，弹窗全部关闭后自动还原；已传 onFullscreenRequest 时走宿主的全屏方法。弹窗期间宿主主动调用 setFullscreen 后，关闭弹窗不再自动还原

遮罩样式

CocosGameWeb.open({
  // ...
  dialogScope: 'fullscreen',
  dialogMask: { color: '#000000', opacity: 0.8 },
  // dialogMask: { visible: false },  // 遮罩透明，但仍拦截点击，防止误触牌桌
  onDialogChange(isVisible) {
    console.log(isVisible ? '游戏弹窗打开' : '游戏弹窗全部关闭');
  },
});
字段规则
visible默认 true；false 时遮罩完全透明
color#RRGGBB；不传使用游戏默认紫青渐变
opacity0~1；只传颜色时默认 0.6

非法值自动回落为默认样式，不会影响游戏运行。

手机竖屏宿主弹窗

手机竖屏内嵌时游戏区域较小，与 Android / iOS SDK 一样，下注、记录与规则、退出确认改由 SDK 在宿主页面上展示；进入全屏后仍使用游戏内弹窗。宿主无需额外开发，默认开启。

弹窗竖屏内嵌（宿主页面）全屏
下注白色卡片紧贴游戏容器下方；多注区时先选注区，点选筹码即下注并收起，下注时间结束自动收起游戏内弹窗
记录与规则从底部弹出 75% 高度面板，「我的记录 / 游戏规则」两个页签；点遮罩或下拉关闭
退出确认页面居中确认框「离开 / 取消」，点遮罩视为取消
CocosGameWeb.open({
  // ...
  hostDialogs: true,              // 默认 true；false 时手机竖屏也用游戏内弹窗
  dialogMask: { color: '#000000', opacity: 0.6 },  // 同时作用于宿主页面弹窗遮罩

  onExitRequest(decide) {         // 可选：改用宿主自己的退出确认框
    showMyConfirm({
      onLeave: () => decide(true),
      onCancel: () => decide(false),
    });
  },
});
  • 判断条件：手机浏览器 / App WebView 且游戏未全屏。电脑浏览器始终使用游戏内弹窗。
  • 游戏容器下方需留出下注卡片的位置（约 120~200px，随注区与筹码数量变化），卡片作为容器的下一个兄弟元素插入。
  • 弹窗打开时锁定宿主页面滚动，关闭后恢复；进入全屏或 close() 时自动收起全部宿主弹窗，未决定的退出确认按取消处理。
  • 传入 onExitRequest 时必须调用一次 decide，否则玩家保持在座。
  • 确认离开后，离座成功时回调 onPlayingStateChange(false)（0.2.2），宿主可据此刷新页面上的在座状态。

宿主自绘下注 / 记录 / 退出

手机竖屏内嵌时，宿主可以用自己的界面替换 SDK 自带的下注卡片、记录与规则面板、退出确认框：传入对应回调即接管，未传时仍由 SDK 展示；全屏时始终使用游戏内弹窗。规则与 Android / iOS SDK 0.2.0 一致。

界面接管回调宿主调用
下注onBetOptions、onBetClosed、onBetResultsubmitBet、CocosGameWeb.createClientBetNo()
记录与规则onShowRecords、onRecordsUpdatedqueryRecords、loadMoreRecords
退出确认onExitRequestdecide(true / false)
const game = CocosGameWeb.open({
  // ...
  onBetOptions(options) {
    // { roundId, countdownSeconds, deadline(毫秒时间戳), areas: [{ areaCode, areaName }], chipsCent: [100, 500] }
    showMyBetPanel(options);
  },
  onBetClosed(roundId) {          // 截止、进入全屏或关闭时收起
    hideMyBetPanel(roundId);
  },
  onBetResult(result) {
    // { roundId, clientBetNo, areaCode, amountCent, isSuccess, errorMessage, balanceCent }
    showMyBetResult(result);
  },
  onShowRecords(content) {        // 玩家点击记录：{ title, sections, records }
    showMyRecords(content);
  },
  onRecordsUpdated(records) {     // 切换页签、加载更多后的新数据
    updateMyRecords(records);
  },
  onExitRequest(decide) {
    decide(window.confirm('确定离开？'));
  },
  onEvent(event, payload) {
    if (event === 'wallet.balance_changed') updateMyBalance(payload.balanceCent);
  },
});

// 玩家点筹码下注
const isSent = game.submitBet({
  roundId: options.roundId,
  areaCode: selectedArea.areaCode,
  amountCent: 100,
  clientBetNo: CocosGameWeb.createClientBetNo(),
});

// 记录页签切换 / 加载更多
game.queryRecords({ isHistory: true });
game.loadMoreRecords(true);
  • 同一局只回调一次 onBetOptions；进入全屏会收到 onBetClosed，回到竖屏后按剩余倒计时重新回调 onBetOptions。
  • SDK 在本地校验注区、筹码与截止时间，不合法时 submitBet 返回 false 并不发送。
  • clientBetNo 最长 64 个字符，用于幂等：提交中或已成功的单号重复提交会被忽略，失败后可用同一单号重试。
  • 金额单位均为分；钱包余额变化通过通用事件 wallet.balance_changed { balanceCent } 下发。
  • 以上回调仅在 hostDialogs 未关闭时生效。完整示例见 Demo 页「宿主自绘下注 / 记录 / 退出」选项。

交互时序

以下回调仅在手机竖屏内嵌（非全屏）时触发，全屏时由游戏内弹窗展示；收到 onFullscreenChange(isFullscreen) 进入全屏时，建议宿主收起自绘的下注和记录面板。游客不会触发下注与记录回调，改为发送 auth.login_required。

时机SDK / 宿主调用宿主处理
进入下注阶段（每局一次）回调 onBetOptions(options)显示下注面板：注区、筹码、倒计时
玩家选注区和筹码宿主调用 game.submitBet({ roundId, areaCode, amountCent, clientBetNo })结果经 onBetResult(result) 返回，按 clientBetNo 对应
下注截止或离局回调 onBetClosed(roundId)收起下注面板
玩家点击记录与规则回调 onShowRecords(content)打开记录面板，首屏数据在 records 字段
切换本桌 / 历史、筛选、搜索宿主调用 game.queryRecords({ isHistory, filterKey, periodIndex, keyword })先回调 onRecordsUpdated(records)（list.status 为 loading），查询完成再回调一次
滑到列表底部宿主调用 game.loadMoreRecords(isHistory)结果经 onRecordsUpdated(records) 返回，整份替换即可
关闭记录面板无需通知游戏宿主自行关闭

记录数据字段

展示记录回调与记录更新回调的 JSON 由游戏统一生成，三端一致；文案均已本地化，宿主直接展示即可。

字段说明
title / roomTag规则标题、房间标签（仅展示记录回调）
sections[]规则分组：title、items[]（title、value、description）（仅展示记录回调）
records首屏记录，结构同下（仅展示记录回调；记录更新回调直接是这份结构）
currentTab / historyTab「本桌」「历史」页签文字
filters[]下注类型筛选 { key, label }，全部为 all；查询时传 filterKey
current.items[]本桌每局：title、detail、result、tone、type
current.banner / stats[]本桌提示条、统计项 { label, value, tone }
history.sessions[]历史场次：key、title、amount、tone、detail、source、daysAgo、types[]、rounds[]（结构同 current.items）
history.periods[]时间范围 { label, days }，查询时传下标 periodIndex
history.sources[] / searchPlaceholder / searchButton来源列表、搜索框占位与按钮文字
current.list / history.list列表状态：status（loading / ready / error）、hasMore、isLoadingMore、message（错误信息）
emptyText / footer空状态文字；底部文字 loading、loadMore、noMore、retry
tone金额颜色：win / lose / draw / normal
  • 界面状态：list.status 为 loading 时显示加载中；为 error 时显示 message 与重试（重试即再次查询）；列表为空显示 emptyText；hasMore 为 true 且未在加载时，滑到底部加载更多。
  • SDK 自带界面会再按 daysAgo（所选时间范围）、source、搜索关键字与 types 在本地过滤 history.sessions，宿主可参照实现。

游客观战（仅直播间）

未登录用户可以游客身份进入直播间观战，群聊必须登录。session 不传 liveUserId / liveToken 即为游客；游客只能观战：牌桌不显示右上角余额，下注阶段不弹下注窗，也不通知宿主。

const game = CocosGameWeb.open({
  container: document.getElementById('GameContainer'),
  gameUrl: 'https://niuniu-web-test.pages.dev/',
  session: {
    sceneType: 1,              // 游客仅支持直播间
    sceneId: '3947124',
    deviceId: 'h5-xxx',        // 建议传入宿主自己的稳定设备号，不传时自动生成
  },
  onEvent(event, payload) {
    if (event === 'auth.login_required') showLoginPrompt(payload.action);
  },
});
auth.login_required 载荷触发操作
{ action: 'join' }点击立即加入
{ action: 'records' }点击记录与规则
{ action: 'fullscreen' }点击全屏（旋转大屏），不会进入全屏
  • 需要登录的操作统一通过 onEvent 发送 auth.login_required，游戏内不弹提示，由宿主提示登录。
  • 建议留在游戏页提示登录或跳转登录页；登录成功后再 game.close()，并用登录会话重新 CocosGameWeb.open。不要在事件回调里直接关闭牌桌。
  • 建议宿主传入稳定的 deviceId（1~128 个字符，不含空白与控制字符），例如宿主自己的设备号或匿名用户 ID。不传时 SDK 自动生成并保存在游戏域名下的 localStorage，但游戏以 iframe 嵌入，Safari 等浏览器会按宿主隔离甚至定期清理第三方存储，同一用户的游客编号可能变化。
  • 带了任一登录字段即按登录严格校验，不会降级为游客；游客传 sceneType: 2 会启动失败。

迷你条

宿主可把牌桌缩小为 362:50 的横条（例如聊天页顶部），迷你条显示局数、阶段、头像、手牌与结算输赢、余额、展开和退出按钮：入座时显示自己，旁观时显示庄家，无庄家时显示问号头像。

const game = CocosGameWeb.open({
  // ...
  onExpandRequest() {                       // 玩家点击迷你条展开按钮
    container.classList.remove('game-mini');
    game.setMiniMode(false);
  },
});

// 缩小：先把容器改成 362:50，再通知游戏，并传入容器所在页面底色
container.classList.add('game-mini');      // .game-mini { aspect-ratio: 362 / 50; }
game.setMiniMode(true, '#F4F5F8');
  • 先调整容器尺寸再调用 setMiniMode，游戏按容器比例绘制迷你条。
  • 圆角由游戏绘制，圆角外填充 backgroundColor（#RRGGBB，缺省白色），请与容器所在页面底色一致。
  • 迷你模式下不可进入全屏；处于全屏时进入迷你条会先退出全屏。
  • 游戏内下注弹窗在迷你条期间收起，展开后本局未下注会重新弹出。
  • 退出按钮与牌桌返回按钮行为一致（onBack、onExitRequest 同样生效）。
  • 未传 onExpandRequest 时，点击展开由 SDK 直接调用 setMiniMode(false)，容器尺寸需宿主自行恢复。

通用事件

接收游戏事件

CocosGameWeb.open({
  // ...
  onEvent(event, payload) {
    if (event === 'niuniu.wallet.open') openWalletPage();
  },
});

向游戏发送事件

game.sendEvent('niuniu.wallet.closed', { isBalanceChanged: true });
  • 事件名必须匹配 ^[a-z][a-z0-9_.-]{0,63}$，建议带模块前缀；不合法时 sendEvent 抛出错误。
  • 载荷为普通对象，可省略。
  • Token、密码等敏感数据不得放入通用事件。

宿主与 SDK 职责

宿主负责

  • 账号登录、Token 刷新和退出。
  • UID、Token、Scene Type、Scene ID。
  • 提供游戏容器与页面导航。
  • 返回、会话失效后的页面处理。
  • 钱包、充值等自有业务页面。
  • 登记宿主域名。

SDK 负责

  • 创建与销毁游戏 iframe、会话传递。
  • 大厅 HTTP、WebSocket、重连和快照恢复。
  • 入座、下注、结算与界面状态。
  • 内嵌与全屏切换、等比适配。
  • 记录与规则、下注弹窗、离座确认。
  • 通用事件桥。

安全说明

  • 游戏运行在独立域名的 iframe 中，宿主页面不加载游戏业务代码，双方页面数据互相隔离。
  • SDK 只接收来自本 iframe、且来源为游戏域名的消息；游戏只接受白名单域名父页面的消息，并在首次会话后锁定父页面域名。
  • 会话只在游戏就绪后通过 postMessage 定向发给游戏域名，不写入地址栏、不落本地存储。
  • 宿主页面如配置了 CSP，需要允许游戏域名：frame-src https://niuniu-web-test.pages.dev（正式域名另行提供）。
  • iframe 已设置 allow="autoplay; fullscreen"，宿主外层若还有 iframe，也需放行这两项。

我的记录

「我的记录」由游戏内置实现，宿主无需调用任何 API、无需注册回调。用户在游戏内点击「规则」按钮，切换到「我的记录」页签即可查看本人注单；手机竖屏时该面板由 SDK 在宿主页面展示，数据仍由游戏查询。如需用宿主自己的界面展示，见「宿主自绘」。

常见问题

iframe 一直黑屏，没有任何回调

多数是宿主域名未登记：游戏控制台会打印「拒绝非白名单父页面消息」。确认登记的源与地址栏完全一致（协议、域名、端口）。本地联调时注意 localhost 与 127.0.0.1 不是同一来源。

提示「登录状态已失效，请重新登录」

确认 liveUserId 与 liveToken 匹配、未过期，且与 gameUrl 属于同一环境。

大厅没有可用桌

确认 Scene Type、Scene ID 与后台开桌场景一致，指定的 tableId 仍有效。

手机上没有声音

手机浏览器要求用户先与页面交互才能播放声音。建议由用户点击按钮后再调用 open。

全屏后页面不能滚动

默认全屏会锁定页面滚动，退出全屏或 close() 后自动恢复。如需自行控制，使用「自定义全屏」。

单页应用切换路由后游戏还在后台运行

组件卸载时调用 close()，参考快速开始中 Vue / React 写法。

上线验收清单

  • 宿主正式域名已登记，使用 HTTPS。
  • UID、Token、Scene Type、Scene ID 均来自宿主登录态。
  • 能进入牛牛桌并收到实时阶段。
  • 入座、离座、下注和结算正常。
  • 记录与规则、下注弹窗、离座确认关闭后按钮仍可点击。
  • 内嵌、全屏往返后全部按钮仍可点击，弹窗遮罩覆盖正确。
  • 手机竖屏内嵌：下注卡片显示在游戏下方且能下注，记录与规则、退出确认在宿主页面弹出；切到全屏后改为游戏内弹窗。
  • 宿主自绘时：每局只收到一次下注选项，倒计时结束或进入全屏收到 onBetClosed，回到竖屏按剩余时间重新收到；下注结果与 wallet.balance_changed 余额正确。
  • 返回离开、再次进入游戏正常；路由切换后 iframe 已移除。
  • 切到后台再返回能够恢复桌态。
  • Token 失效后能回到宿主登录流程；打开游戏时 Token 已失效，收到 onSessionInvalid 且不出现黑屏。
  • 点击「退出」离座后收到 onPlayingStateChange(false)，关闭游戏后收到 onClose。
  • iOS Safari、Android Chrome 及宿主 App 内 WebView 至少各完成一次冒烟测试。
  • 未在日志或埋点中记录 Token、密码。
